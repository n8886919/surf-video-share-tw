# Product

Before uploading, check for the same original file among all accounts' public videos uploaded within the previous 24 hours. A match presents「最近 24 小時已有相同檔案的公開影片，可以先查看，避免重複上傳。」with「查看已有影片」and instructions to select a different file or report a suspected mistake with the displayed public video ID. Viewing revalidates public metadata and opens the existing rate-limited player in the upload screen; closing it preserves the chosen file and fields, without requiring a share token or creating an export link. No override button or automatic overwrite is provided. This is an exact-file check based on an unverified client claim, not visual similarity detection or an ownership determination. Other accounts' private, pending, failed, expired and delisted videos are excluded. Old videos without a stored original-file fingerprint cannot be matched; changing the filename alone still matches, while edits/re-encoding can change the fingerprint. Hashing failure leaves the core upload flow available. The 24-hour window is measured from the first server-recorded upload completion, not capture time, calendar midnight or the most recent status check.

上傳前填妥浪點與拍攝日期時間（以 `Asia/Taipei` 處理，控制項使用裝置原生日期時間選擇器）；移除預設浪點與尚未選檔時的時間來源提示。檢查檔案、取得票券、直接傳送影片與確認接收期間，以原生 modal dialog 阻擋底層點擊及鍵盤操作、模糊遮罩和離頁提醒保護流程。進度條的百分比只來自實際傳送位元組；檢查與建票階段不捏造百分比。交付伺服器後回到「我的」，轉檔可繼續進行；我的頁對轉檔影片最多每 20 秒重查一次、共六次，離頁即停止。自己影片的播放視窗不提供檢舉按鈕，公開搜尋影片仍保留檢舉。

浪點名稱下方顯示該浪點全部合格公開影片數，與相似度命中數無關。「找影片」按鈕上方以單行 `資料更新：CWA（2小時前）、MFWAM（5小時前）` 顯示目前所選目標資料的本站收錄年齡；缺資料明示，API 錯誤不冒充更新時間。這不是模型起報時間，MFWAM 的模型時間仍未知。移除初次進入的選擇／搜尋操作提示。

## Definition

彼日浪影讓使用者選擇浪點與一個未來預報時間，再用同浪點、相似歷史預報下的公開實拍，回答「這種預報下，浪實際會長怎樣」。個人影片時間軸、收藏與公開名稱是促進上傳的誘因，不是私人影片儲存服務。

完整理念與公地、永續經營邊界見 `docs/PROJECT_PRINCIPLES.md`。

## MVP scope

- 正式浪點：烏石港、雙獅、無尾、蜜月灣、金樽、北東河、漁光島、南灣、中角灣、福隆、環保、北濱、磯崎、九棚、佳樂水、松柏港、翡翠灣、萬里、外埔、白沙灣。
- 內部測試最多註冊 100 位使用者；額滿後既有使用者仍可登入，新 LINE 使用者不建立帳號。
- Product `0.27` 保留真人點選的 LINE 自動登入為主要入口；帳密登入只是明確標示的選用備援。重複回呼顯示確認中，原本開始登入的入口憑獨立短效第一方 cookie 完成登入並確認 `/me`；返回前景時有界重查，不無限輪詢。回到其他瀏覽器／容器時引導回原入口，cookie 不可用時明確提示；影片清單失敗不能把已登入顯示成登入失敗。仍保留非憑證診斷編號，不要求密碼、完整回呼網址或 token。自動化測試不等於 Android／iPhone 實機驗收；安全機制、收集期限與保留方式見 `docs/OPERATIONS.md`。
- 公開訪客只需在「彼日浪影」選浪點、`Asia/Taipei` 日曆日偏移 0–4 與當日 05:00–19:00 的整點；不可選分鐘或已經過去的時間。日期與小時各使用一條 slider。上傳與「我的」需要 LINE 登入。
- 彼日浪影只有一個實拍結果區。上半部的相似結果在日偏移 0–2 必須同時有可比較的 CWA 與 MFWAM 目標／歷史快照；兩個來源各自計算、各自通過 50% coverage，再各佔綜合分數 50%。日偏移 3–4 明確使用 MFWAM-only，候選只須通過 MFWAM coverage，顯示的相似度就是 MFWAM 分數。兩種模式都不平均原始值。左側以所選日期和「預報資料」固定顯示一次比較基準；右側可水平捲動的每張實拍卡只顯示影片時間中該來源實際具備的特徵與 swell 配對，不重複目標值或來源名稱。CWA 顯示總浪與潮位但不顯示潮位 LocationId；MFWAM 顯示總浪、湧浪分量與風浪，不顯示其未提供的風或潮汐。相似實拍縮圖只疊上唯一的「相似度 N%」，不顯示拍攝日期時間，不提供來源切換。下半部另外列出同浪點、後端查詢時間往前兩小時內（含邊界）的全部公開實拍；這個滾動時間窗不受所選預報時間影響、不要求完整歷史預報、不計分，也不影響 matching 排序。
- 上傳 10–60 秒、原始檔最多 200 MB（200,000,000 bytes）、拍攝時間不得晚於現在、不得早於現在 168 小時以上，且實際台北拍攝時間須在 05:00–19:59。拍攝時間保留實際分鐘與秒，不強迫整點。瀏覽器不先轉檔；原始檔直接上傳後由影音供應商處理。後端以伺服器時間驗證建立請求，並以影音供應商回報的真實片長決定是否可公開，使用者修改瀏覽器欄位、request payload 或檔案 metadata 都不能建立未來影片、提交限制時段外影片或繞過片長限制。
- 上傳頁順序為公開／CC0 說明（無「公開提醒」標題）、顯示公開名稱、上傳卡片、同排浪點／拍攝時間、「確認上傳」。公開說明以 11px 呈現；點「更多」開可關閉的原生 modal，保留完整人物入鏡說明及官方資料，不推動底層版面、不增加同意步驟。「顯示公開名稱」在有 `display_id` 時每次開啟預設啟用。
- 卡片標題為「上傳浪影」，旁邊是「說明」文字按鈕；限制文案為「7天內,10-60秒的浪況或衝浪影片」。說明以相同的可關閉視窗呈現 CWA／MFWAM 與歷史資料規則，不承諾搜尋曝光。兩個 88px 高圓角來源按鈕只顯示資料夾／相機圖示，具「選擇影片」／「錄影」無障礙名稱，後者偏好外鏡頭。不支援 HTML capture 的瀏覽器可退回一般影片選擇器。
- 選檔／錄影後，透過暫時的本機 Blob URL 顯示原生影片預覽、片長、大小與「尚未上傳」；不自動播放，不轉檔，不建立 Stream 票券或傳送影片。替換／離開時釋放 URL；取消檔案選擇或新檔驗證失敗保留原有效檔案。無法讀取片長仍依既有規則拒絕選檔，已通過 metadata 驗證但播放格式不支援時提示，不把它視為已上傳。
- 浪點與拍攝時間同排，空值時控制項內顯示「浪點」／「拍攝時間」，選好後只顯示值；不顯示「台北時間」字樣，但 `Asia/Taipei`、必填、168 小時、非未來及 05:00–19:59 驗證保持不變。「浪點與拍攝時間上傳後不可變更」放在「確認上傳」按鈕內第二行。
- 瀏覽器最多讀取 4 MiB QuickTime metadata atom，優先以含明確時區的原始拍攝時間提示，其次是容器建立時間，最後才是標為最低可信度的 `File.lastModified`；無效、未來、超過 168 小時、無時區或無 metadata 時不靜默猜測。來源提示保持可見；不得先預選第一個浪點。
- 有已選影片（含讀取中）時，切至找浪／我的浪影先顯示「影片尚未上傳」，提供「繼續編輯」與「放棄並離開」；前者保留檔案及欄位，後者丟棄暫存並切頁。更多、說明及欄位編輯不觸發離開提醒。選檔後的重新整理／關閉分頁使用原生 beforeunload 提醒；手機強制關閉 App 無法保證觸發，不保存本機影片草稿。正式傳送仍沿用阻擋操作的上傳進度視窗，完成接收後到我的浪影。
- 影片若含足夠精確的 ISO 6709 位置，只在距某正式浪點 750 m 內、與次近浪點至少相差 500 m、座標不確定度不超過 100 m 時提示該浪點。原始座標只在選檔當下於瀏覽器記憶體映射，不顯示、不送出、不保存；不明確時保留上次使用或手動選擇。不得從影像或檔名推測浪點，也不得把目前裝置位置當成既有相簿影片的位置。浪點與拍攝時間須在上傳前填妥，上傳後不可補選或變更；不再提供補拍攝時間功能。使用者不可輸入任何浪況數值。
- 海況抓取失敗不阻擋影音上傳。
- 影片只有在浪點、拍攝時間、上傳與轉檔狀態完整時公開。新上傳缺浪點或拍攝時間時，前端禁止送出且後端拒絕建立票券；既有缺資料影片保持私人，依原七天期限清除。
- 上傳畫面直接說明影片公開後採 CC0 1.0、可下載／修改／轉售／訓練模型且不可撤回；CC0 只涵蓋上傳者有權釋出的著作權，不影響第三人的肖像、隱私或其他權利。不增加勾選或確認步驟，後端保存條款版本。
- 影片以浪況為主。廣角浪況中人物僅附帶入鏡時不要求逐一同意；可辨識人物若成為主要拍攝對象，須先取得本人或未成年人監護人同意，否則裁切或模糊。完整公開說明文案後方的「更多」視窗提供判斷提示、下架途徑及法務部、智慧財產局、憲法法庭與 CC0 官方資料；它不是個案法律保證，也不阻斷上傳流程。
- 信任貢獻者，不做逐片事前人工審核；公開影片的播放視窗需有檢舉入口。若上傳者逐片開啟公開名稱，同一視窗顯示其 `display_id`；管理者仍有下架能力。
- 「問題回報」統一放在頁面右上角圓形問號旁，以三角形驚嘆號呈現；找浪、上傳與我的均可使用。使用者只填 5–300 字問題描述；不要求聯絡方式或其他個資，後端仍不儲存回報者身分或原始位址。
- 上傳者可用 2–24 字元 Unicode 公開名稱，逐片決定是否顯示。LINE 顯示名稱只作為私人預填建議；使用者須儲存為本站公開名稱，且開啟顯示後才會公開。
- 帳號影片頁移除「我的」標題，影片數量放在浪點選擇下方並反映目前篩選；影片依時間排序、可依浪點篩選、可私人收藏自己的影片。上傳者可選填當天玩得開心／不開心與最多 100 字的公開補充；兩者不進 matching、不影響排序，也不延伸成標籤或多人留言串。公開名稱編輯與登出集中在同一個帳號區塊；不提供新影片預設顯示名稱設定，每次上傳由該影片的開關決定。
- 登入者可從公開影片播放視窗或「我的」建立分享連結；連結固定 24 小時有效，網址中的加密權杖把匿名播放歸到匯出者當月共用的 100 次額度。開啟頁面與預覽縮圖不扣額度，匿名訪客按「載入播放器」並取得播放授權時才扣一次；等待期間按鈕立即鎖定，避免重複請求。已登入觀看者不扣匯出者額度。額度用完或連結過期後停止該連結播放，但不改變影片本身的公開／CC0 狀態。重新產生連結不重設額度，也不建立 MP4；分享目標由作業系統決定，不承諾特定 App。「準備下載 MP4」仍是本人影片的獨立動作。分享頁的浪點、台北時間與選用公開名稱濃縮為單行，公開補充明確加上「上傳者補充:」標籤；底部「更多浪影．上傳你的浪影」回到首頁並自動開啟「操作與專案說明」。
- 上傳者在自己的影片縮圖上可直接看到近 90 天播放次數，不必展開更多資訊。只有 Stream Player 實際進入 `playing` 後才記錄，不把縮圖曝光、播放 token 建立或播放器載入算成播放；登入中的上傳者自播不計入，同一訪客重複播放仍分別計算。這個數字隨既有的「我的影片」查詢回傳，不另發前端請求；它不公開、不進 matching、不排序、不產生獎勵或通知。

## Navigation

手機底部固定找浪、上傳兩個純 icon 分頁，各佔一半寬度並填滿底列，以淺底色和頂部指示線標示目前頁面，不使用獨立圓角按鈕或陰影；帳號與影片入口位於右上角，LINE 頭像旁顯示「我的浪影」，未登入、沒有頭像或載入失敗時使用人像圖示。底部分頁不顯示文字，仍提供無障礙名稱和目前頁面狀態。電腦版兩個入口固定在應用外框的獨立底列，內容只在底列上方捲動，不得被導覽列遮住。個人設定保留在「我的」，問題回報移至共用頂列。依管理員實際操作回饋，Product 0.29 將全站管理功能移到獨立 `/admin` 頁；底部只有找浪、上傳，帳號入口在右上角，管理員的「我的」顯示管理後台入口。

## Compact UI behavior

- 找浪操作由上至下為浪點、日期、時間、資料更新時間、「找影片」按鈕、影片結果。進頁、切分頁或調整條件不自動請求 `/matches`；按「找影片」才查詢，等待期間禁止重複送出。未搜尋不顯示空結果；條件變更後隱藏不相符結果並提示按「找影片」。同一次頁面生命週期內保留選擇與上次結果，切回找浪只重新取得浪點公開影片數，不自動重查比對；切離時關閉播放器。最近兩小時影片以最後一次搜尋時的伺服器時間為準，重新按「找影片」才更新。

- 浪點不顯示「浪點」標籤或 select；以和日期格同高同寬的橫向按鈕列呈現。二十個正式浪點皆可選並可送往 API，不再顯示測試佔位按鈕。觸控使用瀏覽器原生水平捲動，以保留 iPhone 的加速與慣性；桌面滑鼠拖曳與滾輪也可滑動。手機不提供長按排序；滑鼠約 450 ms 長按後按鈕放大並改為排序。拖曳只在游標跨過相鄰按鈕的靜態 layout 中點與滯後門檻時換一格，短暫鎖定避免動畫命中造成來回抖動；其他按鈕以短動畫移位，拖曳中的按鈕不套該位移。按鈕文字不可選取，行動裝置長按不得開啟複製／系統選字。順序只存本機。找浪與帳號影片頁的浪點按鈕依既有 region 以北部（藍）、東北部（綠）、東部（紫）、西南部（暖黃，合併 West/South）呈現；只改按鈕顏色，不新增分組標題、不改排序、尺寸或資料分類。
- 日期選擇是五格離散 bar，不是連續刻度。每格直接以放大的文字顯示月／日與星期，不顯示日偏移數字，也不另放「日期」與所選日期摘要。第 1–3 天標示 CWA＋MFWAM，第 4–5 天標示 MFWAM-only。
- 相似結果左側固定一張 84px 寬的所選日期「預報資料」卡，寬度須容納單行 `Météo-France` 與單行浪高／方向／週期值，不縮小既有字體；`MFWAM` 明確置於來源名稱下一行。右側所有歷史實拍放在同一條可左右滑動的候選列，以淺底色和內框強調整個區塊；每張縮圖由 230 × 168px 縮為 161 × 117.6px（70%）；兩側使用相同的來源表頭高度、資料列高度與分隔位置，使每個來源和特徵逐列對齊。候選卡只列實拍當時該來源有值的模型特徵，不重複預報來源名稱或目標預報。每個來源區塊以「相似度」和百分數作為表頭。候選縮圖本身提供明確播放控制，只疊上綜合相似度；拍攝時間仍保留於播放視窗及無障礙名稱；按下後以影片視窗播放，不建立「已選實拍」欄位。其下的「即時影片（近 2 小時）」列以同樣的水平滑動與明確播放控制顯示全部合格公開影片，只疊拍攝時間而不冒充相似度，縮圖由 190 × 112px 縮為 133 × 78.4px（70%）。每一列最多保留一個作用中的播放器。
- 播放資料若含供應商回傳的原始寬高，播放視窗依該比例呈現；直式影片置中並限制於可視高度，缺少尺寸時才退回 16:9。
- 「我的」影片卡左上顯示浪點與拍攝時間，縮圖下方直接顯示私人近 90 天播放次數；右上並排收藏與通用的橫向三點「更多資訊」圖示。更多資訊展開後才顯示開心／不開心、上傳者補充、是否顯示公開名稱、影片時間的模型資料，以及純 icon 的分享連結與 MP4 下載動作。模型資料固定先列參與 matching 的 CWA／MFWAM，再列 collect-only 的 ECMWF WAM／GFS Wave 0.16°／DWD GWAM；總浪、總湧浪、主／次／第三浪、風浪、風與潮汐欄位依來源能力顯示，CWA 潮汐同時標記實際 F-A0021-001 LocationId，缺值保持「—」，collect-only 明示不影響相似度。
- 更多資訊內的預報使用緊湊兩列：第一列為「預報、主浪（浪高／浪向／週期）、次浪（浪高／浪向／週期）、風（風速／風向）」標題，第二列放對應數值；缺值顯示 `—`，來源仍分開且不得平均。
- `/admin` 沿用 LINE 登入，只有後端指定的管理員可讀取與操作。全站檢舉按影片分組、可預覽；管理員可用「測試／檢舉不成立」保留並結案，或依檢舉原因下架；已處理清單可複查及恢復公開。另含網站問題回報、管理操作紀錄與限量流程日彙總。一般使用者不載入管理資料，登入本身不授予管理權限。
- 「我的」影片卡只有在需要注意時顯示「上傳未完成，請重新上傳／等待轉檔／影片轉檔中／影片處理失敗，請重新上傳／資料不完整／已下架／舊版不公開」等狀態；完整且已公開的影片不顯示「公開」標籤。
- 最上方品牌列左側只顯示 Logo（保留品牌替代文字）；右側提供圓形問號按鈕，按下後直接以視窗顯示目前產品版本（自 `0.1` 起）、操作說明、核心目的與本文件所依據的 Purpose and position，不跳轉到其他頁面。公開分享頁保留原有品牌與測試版標籤。LINE 登入完成並由 /me 確認登入後，主 App 自動開啟操作與專案說明一次；只恢復已有登入、重開 App 或重新整理時不彈出。
- 帳號區塊使用 `公開名稱: xxxxx` 加鉛筆圖示表達可編輯；它編輯的是本站 `display_id`／公開名稱，不是 LINE subject。這裡不再顯示目前 id 副文或新影片名稱預設開關，登出接續排列。
- 為避免本人反覆播放同一影片造成重複傳輸，實作時先評估重用仍有效的播放器／短效播放資料及瀏覽器快取。不得繞過每次首次播放的公開生命週期檢查、延長簽章期限、永久保存影片位元組或把產品變成離線私人雲端硬碟。

## Matching

本節定義產品行為；完整且與實作同步的分數公式、權重、缺值、配對與 tie-break 規格見 [Matching algorithm](MATCHING.md)。

每個 provider/model/run 都是獨立特徵與不可變快照，保存 `snapshot_kind`、`issued_at`／`model_run_at`、`valid_at`、`lead_hours` 與網格來源。未來查詢只使用查詢當下最新可得的 `forecast`；歷史影片優先使用一般 live forecast 的 bounded recent-past window 自然取得、有效時間接近拍攝時間的 `historical_forecast`，否則退回拍攝當時最新可得的 `forecast`。兩者都不要求 `lead_hours` 相同，不呼叫專門舊 Historical Forecast mode，也不回補既有影片。

公開查詢限定日曆日偏移 0–4。偏移 0–2 位於 CWA 已驗證的 0–72 小時與 MFWAM 的共同範圍，任一來源缺少目標或歷史快照就排除該影片；兩個來源各自正規化並通過 50% coverage 後各佔 50%。偏移 3–4 只要求 MFWAM。兩種模式都不外推、複製或用另一來源補值；ECMWF、GFS 與 GWAM 不進目前排序。

同浪點所有合格公開影片都能參與相似度比對，不再只取最近拍攝的 20 支；較舊但浪況更接近的影片仍可排在前面。歷史查詢只讀參與 matching 的 CWA／MFWAM，其他三個模型仍獨立保存並顯示於「我的影片」。拍攝時間只用於取得影片當時的模型快照，不以影片新舊或與目標的時間差加減相似度。

第一版使用可解釋的同浪點距離排序。資料量尚小時，不以非監督學習取代基準：聚類可在累積足夠完整影片後做離線探索，但不能把叢集編號當浪況真相。

## Condition features

可用時保存總浪、總湧浪、主／次／第三湧浪與風浪的浪高／方向／週期，以及來源提供的 peak period；另存潮高、潮汐斜率與狀態、風向／風速／陣風。DWD GWAM 的 `swell_wave_*` 明確映射為總湧浪，MFWAM／GFS 的同名欄位才映射為第一湧浪分量，不能因共享欄名而混淆語意。可由原始值導出相對岸向、能量代理值，但不覆寫來源資料。

相似度維持無標籤、可解釋的同浪點距離排序。總浪、湧浪系統、風浪、風與潮汐各有固定群組預算；加入次湧浪不會提高湧浪群組總權重。主、次湧浪視為無順序的兩個浪系，選擇距離較小的合法配對，並依目標浪高平方分配湧浪群組內權重。方向差使用圓形 cosine distance，使 359°／1° 保持接近、小角度差異受到較小懲罰，而 90°／180° 差異快速增加。每個來源與候選都保留演算法實際選出的配對；比較畫面以目標浪系為列，並在實拍欄明示候選的原始「主湧浪／次湧浪」標籤，不依列順序重算或改名。缺值仍是未知而不是零；每個 provider 獨立計算覆蓋率與距離，原始 feature 永不跨來源平均。

## Non-goals

不做任意長影片、原始上傳檔取回、超過七天回填、使用者手填浪況、私人雲端硬碟、點數、廣告、付費、公開留言串、複製第三方浪點內容，或早期黑盒 ML 排名。
