# Product

## Definition

彼日浪影讓使用者選擇浪點與一個未來預報時間，再用同浪點、相似歷史預報下的公開實拍，回答「這種預報下，浪實際會長怎樣」。個人影片時間軸、收藏與公開名稱是促進上傳的誘因，不是私人影片儲存服務。

完整理念與公地、永續經營邊界見 `docs/PROJECT_PRINCIPLES.md`。

## MVP scope

- 首波浪點：烏石港、雙獅、無尾、蜜月灣、金樽、北東河、漁光島、南灣。
- 內部測試最多註冊 100 位使用者；額滿後既有使用者仍可登入，新 LINE 使用者不建立帳號。
- 公開訪客只需在「彼日浪影」選浪點、`Asia/Taipei` 日曆日偏移 0–4 與當日 05:00–19:00 的整點；不可選分鐘或已經過去的時間。日期與小時各使用一條 slider。上傳與「我的」需要 LINE 登入。
- 彼日浪影只有一個實拍結果區。日偏移 0–2 的影片必須同時有可比較的 CWA 與 ECMWF 目標／歷史快照；兩個來源各自計算、各自通過 50% coverage，再各佔綜合分數 50%。日偏移 3–4 明確使用 ECMWF-only，候選只須通過 ECMWF coverage，顯示的相似度就是 ECMWF 分數。兩種模式都不平均原始值。縮圖疊上 24 小時制拍攝時間與唯一的「相似度 N%」，下方列出實際參與評分的來源特徵；不顯示獨立「目前預報」、固定「所選預報」欄或來源切換。
- 上傳 10–60 秒、原始檔最多 200 MB（200,000,000 bytes）、拍攝時間不得晚於現在、不得早於現在 168 小時以上，且實際台北拍攝時間須在 05:00–19:59。拍攝時間保留實際分鐘與秒，不強迫整點。瀏覽器不先轉檔；原始檔直接上傳後由影音供應商處理。後端以伺服器時間驗證建立與補資料請求，並以影音供應商回報的真實片長決定是否可公開，使用者修改瀏覽器欄位、request payload 或檔案 metadata 都不能建立未來影片、提交限制時段外影片或繞過片長限制。
- 上傳頁先以單一卡片呈現「上傳影片」、10–60 秒與 05:00–19:59 規則、可展開的貢獻說明，以及兩個不顯示文字但保留無障礙名稱的圓形影片來源 icon。說明必須誠實表示系統會依拍攝時間與浪點比對當時可得的 CWA 與 ECMWF 浪況，未來相似預報搜尋「可能」使用這段實拍，不承諾曝光。兩個入口分別是「選擇影片」與偏好外鏡頭的「錄影」；不支援 HTML capture 的瀏覽器可退回一般影片選擇器，兩者沿用同一套 10–60 秒、200 MB 與 direct-upload 驗證。瀏覽器最多讀取 4 MiB QuickTime metadata atom，優先以含明確時區的原始拍攝時間提示，其次是容器建立時間，最後才是清楚標為最低可信度的 `File.lastModified`；無效、未來、超過 168 小時、無時區或無 metadata 時不靜默猜測。欄位保持可見、可編輯並要求送出前確認。
- 影片若含足夠精確的 ISO 6709 位置，只在距某正式浪點 750 m 內、與次近浪點至少相差 500 m、座標不確定度不超過 100 m 時提示該浪點。原始座標只在選檔當下於瀏覽器記憶體映射，不顯示、不送出、不保存；不明確時保留上次使用或手動選擇。不得從影像或檔名推測浪點，也不得把目前裝置位置當成既有相簿影片的位置。浪點須在上傳前選定且不可稍後補選或變更，只有拍攝時間可在七天內補齊。使用者不可輸入任何浪況數值。
- 海況抓取失敗不阻擋影音上傳。
- 影片只有在浪點、拍攝時間、上傳與轉檔狀態完整時公開。缺拍攝時間者只在「我的」顯示，七天內可補，逾期刪除。
- 上傳畫面直接說明資料補齊並公開後採 CC0 1.0、可下載／修改／轉售／訓練模型且不可撤回；CC0 只涵蓋上傳者有權釋出的著作權，不影響第三人的肖像、隱私或其他權利。不增加勾選或確認步驟，後端保存條款版本。
- 影片以浪況為主。廣角浪況中人物僅附帶入鏡時不要求逐一同意；可辨識人物若成為主要拍攝對象，須先取得本人或未成年人監護人同意，否則裁切或模糊。完整公開提醒文案後方的行內「更多」展開判斷提示、下架途徑及法務部、智慧財產局、憲法法庭與 CC0 官方資料；它不是個案法律保證，也不阻斷上傳流程。
- 信任貢獻者，不做逐片事前人工審核；公開影片的播放視窗需有檢舉入口。若上傳者逐片開啟公開名稱，同一視窗顯示其 `display_id`；管理者仍有下架能力。
- 「問題回報」入口只放在登入後的「我的」。使用者只填 5–300 字問題描述；不要求聯絡方式或其他個資，後端仍不儲存回報者身分或原始位址。
- 上傳者可用 2–24 字元 Unicode 公開名稱，逐片決定是否顯示。LINE 顯示名稱只作為私人預填建議；使用者須儲存為本站公開名稱，且開啟顯示後才會公開。
- 「我的」依時間排序、可依浪點篩選、可私人收藏自己的影片。上傳者可選填當天玩得開心／不開心與最多 100 字的公開補充；兩者不進 matching、不影響排序，也不延伸成標籤或多人留言串。公開名稱編輯、登出與問題回報集中在同一個帳號區塊；不提供新影片預設顯示名稱設定，每次上傳由該影片的開關決定。
- 登入者可從公開影片播放視窗或「我的」建立分享連結；連結固定 24 小時有效，網址中的加密權杖把匿名播放歸到匯出者當月共用的 100 次額度。開啟頁面與預覽縮圖不扣額度，匿名訪客按「載入播放器」並取得播放授權時才扣一次；等待期間按鈕立即鎖定，避免重複請求。已登入觀看者不扣匯出者額度。額度用完或連結過期後停止該連結播放，但不改變影片本身的公開／CC0 狀態。重新產生連結不重設額度，也不建立 MP4；分享目標由作業系統決定，不承諾特定 App。「準備下載 MP4」仍是本人影片的獨立動作。分享頁的浪點、台北時間與選用公開名稱濃縮為單行，公開補充明確加上「上傳者補充:」標籤；底部「更多浪影．上傳你的浪影」回到首頁並自動開啟「操作與專案說明」。
- 上傳者在自己的影片縮圖上可直接看到近 90 天播放次數，不必展開更多資訊。只有 Stream Player 實際進入 `playing` 後才記錄，不把縮圖曝光、播放 token 建立或播放器載入算成播放；登入中的上傳者自播不計入，同一訪客重複播放仍分別計算。這個數字隨既有的「我的影片」查詢回傳，不另發前端請求；它不公開、不進 matching、不排序、不產生獎勵或通知。

## Navigation

手機底部固定三個同型、放大的純 icon 入口：找浪、上傳、我的；不顯示 icon 下方文字，仍提供無障礙名稱。電腦版三個入口固定在應用外框的獨立底列，內容只在底列上方捲動，不得被導覽列遮住。個人設定、問題回報與僅管理者可見的檢舉處理直接放在「我的」，不增加第四個分頁或獨立管理頁面。

## Compact UI behavior

- 浪點不顯示「浪點」標籤或 select；以和日期格同高同寬的橫向按鈕列呈現。八個正式浪點皆可選並可送往 API，不再顯示測試佔位按鈕。觸控與滑鼠的水平拖曳、桌面滾輪都可滑動；約 450 ms 長按後按鈕放大並改為排序。拖曳只在游標跨過相鄰按鈕的靜態 layout 中點與滯後門檻時換一格，短暫鎖定避免動畫命中造成來回抖動；其他按鈕以短動畫移位，拖曳中的按鈕不套該位移。水平移動先於長按時進入滑動而不是排序；垂直移動仍交給頁面。按鈕文字不可選取，行動裝置長按不得開啟複製／系統選字。順序只存本機。
- 日期選擇是五格離散 bar，不是連續刻度。每格直接以放大的文字顯示月／日與星期，不顯示日偏移數字，也不另放「日期」與所選日期摘要。第 1–3 天標示 CWA＋ECMWF，第 4–5 天標示 ECMWF-only。
- 所有相似實拍放在同一條可左右滑動的候選列。候選縮圖本身提供明確播放控制，並疊上 24 小時制拍攝時間與綜合相似度；按下後以影片視窗播放，不建立「已選實拍」欄位，頁面最多保留一個作用中的播放器。
- 播放資料若含供應商回傳的原始寬高，播放視窗依該比例呈現；直式影片置中並限制於可視高度，缺少尺寸時才退回 16:9。
- 「我的」影片卡左上顯示浪點與拍攝時間，縮圖下方直接顯示私人近 90 天播放次數；右上並排收藏與通用的橫向三點「更多資訊」圖示。更多資訊展開後才顯示開心／不開心、上傳者補充、是否顯示公開名稱、當時預報，以及純 icon 的分享連結與 MP4 下載動作；icon 仍須有無障礙名稱。
- 更多資訊內的預報使用緊湊兩列：第一列為「預報、主浪（浪高／浪向／週期）、次浪（浪高／浪向／週期）、風（風速／風向）」標題，第二列放對應數值；缺值顯示 `—`，來源仍分開且不得平均。
- 「我的」對管理員直接顯示「待處理檢舉」區塊，不再提供「開啟管理頁面」連結或要求跳往獨立頁面；一般使用者不載入管理資料。
- 「我的」影片卡只有在需要注意時顯示「處理中／待補／已下架／舊版不公開」等狀態；完整且已公開的影片不顯示「公開」標籤。
- 最上方品牌列右側提供圓形問號按鈕，按下後直接以視窗顯示目前產品版本（自 `0.1` 起）、操作說明、核心目的與本文件所依據的 Purpose and position，不跳轉到其他頁面。
- 帳號區塊使用 `公開名稱: xxxxx` 加鉛筆圖示表達可編輯；它編輯的是本站 `display_id`／公開名稱，不是 LINE subject。這裡不再顯示目前 id 副文或新影片名稱預設開關，登出與問題回報接續排列。
- 為避免本人反覆播放同一影片造成重複傳輸，實作時先評估重用仍有效的播放器／短效播放資料及瀏覽器快取。不得繞過每次首次播放的公開生命週期檢查、延長簽章期限、永久保存影片位元組或把產品變成離線私人雲端硬碟。

## Matching

匹配目標是「當時已發布、使用者有機會看到的最新預報」而非事後觀測或重建值。每個 provider/model/run 都是獨立特徵與不可變快照，必須保存 `issued_at` / `model_run_at`、`valid_at`、`lead_hours` 與網格來源。未來查詢使用查詢當下最新可得 run；歷史影片使用拍攝當時最新可得 run，兩者的有效時間都需接近目標時間，但不要求 `lead_hours` 相同。CWA 與 ECMWF WAM 的原始值及來源內距離不平均；日偏移 0–2 只有各自正規化並通過 50% coverage 後的來源分數各佔綜合分數 50%，日偏移 3–4 則只使用 ECMWF 的正規化分數。其他模型未驗證前不納入正式排序。

公開查詢限定日曆日偏移 0–4。偏移 0–2 位於 CWA 已驗證的 0–72 小時與 ECMWF 的共同範圍，任一來源缺少目標或拍攝當時快照就排除該影片；偏移 3–4 只要求 ECMWF。兩種模式都不外推、複製或用另一來源補值。

第一版使用可解釋的同浪點距離排序。資料量尚小時，不以非監督學習取代基準：聚類可在累積足夠完整影片後做離線探索，但不能把叢集編號當浪況真相。

## Condition features

總浪、主湧浪、次湧浪、風浪各自保存浪高／方向／週期；另存潮高、潮汐斜率與狀態、風向／風速／陣風。可由原始值導出相對岸向、能量代理值，但不覆寫來源資料。

相似度維持無標籤、可解釋的同浪點距離排序。總浪、湧浪系統、風浪、風與潮汐各有固定群組預算；加入次湧浪不會提高湧浪群組總權重。主、次湧浪視為無順序的兩個浪系，選擇距離較小的合法配對，並依目標浪高平方分配湧浪群組內權重。方向差使用圓形 cosine distance，使 359°／1° 保持接近、小角度差異受到較小懲罰，而 90°／180° 差異快速增加。每個來源與候選都保留演算法實際選出的配對；比較畫面以目標浪系為列，並在實拍欄明示候選的原始「主湧浪／次湧浪」標籤，不依列順序重算或改名。缺值仍是未知而不是零；每個 provider 獨立計算覆蓋率與距離，原始 feature 永不跨來源平均。

## Non-goals

不做任意長影片、原始上傳檔取回、超過七天回填、使用者手填浪況、私人雲端硬碟、點數、廣告、付費、公開留言串、複製第三方浪點內容，或早期黑盒 ML 排名。
