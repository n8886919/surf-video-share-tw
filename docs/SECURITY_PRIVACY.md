# Security and privacy

- Complete videos are public. The upload screen states the CC0 consequences inline without an extra consent click, and every new upload stores the accepted terms version. Existing unversioned rows are not retroactively exposed as CC0. CC0 applies only to rights the uploader can release; it does not remove a third person's likeness, privacy, or other rights.
- Videos must focus on surf conditions. Incidental people in a wide beach/ocean view do not trigger a product requirement to obtain every person's consent; an identifiable main subject requires their consent, or a parent/guardian's consent for a minor, otherwise the uploader should crop or blur. The inline question-mark help links to official legal/CC0 material, preserves reporting/delisting, and explicitly avoids promising a legal outcome for individual facts.
- A spot is required before upload and cannot be patched later. Records missing capture time are owner-only and expire after seven days; public queries require `public_at`, ready status, spot, capture time, a terms version, and visible moderation state.
- Public output may include the uploader's chosen public name stored as `display_id` only when that video's visibility flag is on. The current LINE display name is stored separately as a private suggestion and returned only to its authenticated owner; it is never copied into `display_id` automatically. LINE subjects and internal user IDs are never selected by public queries.
- Candidate responses expose only a first-party thumbnail path. The thumbnail endpoint rechecks complete, ready, public, terms-versioned, and visible state before consulting Stream; it never returns a thumbnail for an incomplete or delisted row. Stream API credentials stay server-side.
- Playback remains first-party gated even though complete videos are public. Only an explicit play action requests a 15-minute signed Stream iframe URL, after repeating the same lifecycle check. New Stream uploads require signed URLs and restrict playback to the hostname derived from the validated HTTPS `PUBLIC_SITE_ORIGIN`; unsigned legacy objects fail closed. Stream's origin allowlist protects playback embeds/manifests/segments, while signed thumbnails rely on first-party issuance and their five-minute token rather than the playback origin check.
- Playback feedback records a random signed event ID only after the Stream Player emits `playing`. The start endpoint repeats the public lifecycle check, rejects altered/expired tokens, excludes authenticated owner self-play, and stores no viewer ID, session, address, country, or user agent. Events older than 90 days are deleted; owner counts are never public.
- `/v/:videoId` metadata contains only a first-party video ID and thumbnail path. Official share URLs add an AES-GCM opaque token with a 24-hour expiry; exporter identity and quota month are not readable or editable in the URL. Public detail lookup repeats the complete/ready/public/terms/visible boundary and exposes neither internal owner IDs nor Stream UIDs, playback tokens, signed MP4 URLs, private favorites, or playback counts. Opening the page or thumbnail does not consume a share grant.
- All links exported by one account in one Taipei month share 100 anonymous playback grants in D1. Reservation is an atomic conditional update before the Stream provider call, so concurrent requests cannot exceed the application quota; conservative reservations are not refunded after downstream failure. Authenticated viewers do not consume this exporter quota, but link expiry, public lifecycle checks, and burst limits still apply. This controls normal official-link sharing; it is not DRM and cannot revoke CC0 copies or promise that a deliberate client will never use another public playback surface.
- Owner MP4 export requires an authenticated ownership match and repeats the complete/ready/public/terms/visible lifecycle before every provider call. The 15-minute signed token includes download permission, replaces the Stream UID in the returned URL, and is delivered only in a `no-store` response. Pending, private, unversioned, unsigned legacy, and delisted videos fail closed. The Worker does not proxy the encoded bytes and never promises access to the original upload.
- Stream-cost-bearing upload tickets, playback tokens, and owner downloads are rate limited before provider calls. Authenticated upload/download keys use the internal user ID; public playback uses an HMAC of the Cloudflare client address so the raw address is never a limiter key or application log field. Production fails closed when the required binding or key material is unavailable.
- LINE-login creation, product reports, and video reports are anonymous D1-writing routes protected by separate scopes inside one `PUBLIC_WRITE_RATE_LIMITER` namespace. Each scope uses the same HMAC pseudonymization pattern; rejection occurs before D1 access. Product reports remain separate from media moderation and store only the short message, current `find`/`upload`/`mine` view, lifecycle timestamps, and resolving administrator—never reporter identity, contact detail, or raw client address.
- Upload requires authentication, ownership check, provider ID verification, a 200,000,000-byte source-file limit, and 10–60 second duration. The browser does not transcode before the direct provider upload. Browser and API metadata cannot bypass the server-owned future-time check, and publication uses the provider-verified duration.
- Target user-entered data is limited to spot/time, public name, favorite, identity visibility, an optional fun reaction, and one optional 100-character uploader supplement. No manual condition values, uploader GPS, additional subjective tags, or public reply threads. The two optional subjective values never affect matching.
- Production secrets stay server-side. Development mocks require explicit development flags.
- All Worker responses set `Referrer-Policy: strict-origin` so outbound referrers do not include share/query tokens or paths, plus `X-Content-Type-Options: nosniff`. Unexpected API exceptions return only a generic message and request ID; structured server logs correlate that ID with method/path and a bounded, common-secret-redacted error summary without logging request bodies or query strings.
- Internal testing accepts at most 100 registered users. Existing LINE subjects can continue to authenticate after the cap is reached; a verified new subject at capacity creates no user or session, and the UI exposes only a generic capacity message.
- MVP moderation is trust-first: no per-video pre-publication review. Public reports are auditable but do not auto-hide content. Only the project administrator identified by `ADMIN_USER_ID` can list open reports and delist a video; ordinary uploader metadata edits cannot republish a delisted row.
- Reporting does not clear copyright, privacy, music, likeness, or minor-consent risks. Upload terms must put responsibility on the contributor, while legal/privacy/safety reports may still cause first-party delisting.

Deterministic expiry deletion, cost-route burst limits, and the public-write/error/header protections are implemented locally. Public candidate comparison deliberately loads no player, manifest, or video segment before an explicit play action. Real signed Stream upload/thumbnail/playback/origin and owner MP4 paths have passed production/mobile checks; the newer 24-hour share-link quota and adaptive player still need two-phone acceptance after an approved deployment. Before public rollout: exercise expiry and moderation/delisting against isolated staging, verify the deployed public-write limiter and security headers, configure cost alarms, and rehearse backup/restore.
