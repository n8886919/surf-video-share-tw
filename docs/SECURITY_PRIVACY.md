# Security and privacy

- Complete videos are public. The upload screen states the CC0 consequences inline without an extra consent click, and every new upload stores the accepted terms version. Existing unversioned rows are not retroactively exposed as CC0.
- Missing spot/time records are owner-only and expire after seven days; public queries require `public_at`, ready status, spot, capture time, a terms version, and visible moderation state.
- Public output may include the uploader's chosen public name stored as `display_id` only when that video's visibility flag is on. The current LINE display name is stored separately as a private suggestion and returned only to its authenticated owner; it is never copied into `display_id` automatically. LINE subjects and internal user IDs are never selected by public queries.
- Candidate responses expose only a first-party thumbnail path. The thumbnail endpoint rechecks complete, ready, public, terms-versioned, and visible state before consulting Stream; it never returns a thumbnail for an incomplete or delisted row. Stream API credentials stay server-side.
- Playback remains first-party gated even though complete videos are public. Only an explicit play action requests a 15-minute signed Stream iframe URL, after repeating the same lifecycle check. New Stream uploads require signed URLs and restrict playback to the hostname derived from the validated HTTPS `PUBLIC_SITE_ORIGIN`; unsigned legacy objects fail closed. Stream's origin allowlist protects playback embeds/manifests/segments, while signed thumbnails rely on first-party issuance and their five-minute token rather than the playback origin check.
- Owner MP4 export requires an authenticated ownership match and repeats the complete/ready/public/terms/visible lifecycle before every provider call. The 15-minute signed token includes download permission, replaces the Stream UID in the returned URL, and is delivered only in a `no-store` response. Pending, private, unversioned, unsigned legacy, and delisted videos fail closed. The Worker does not proxy the encoded bytes and never promises access to the original upload.
- Stream-cost-bearing upload tickets, playback tokens, and owner downloads are rate limited before provider calls. Authenticated upload/download keys use the internal user ID; public playback uses an HMAC of the Cloudflare client address so the raw address is never a limiter key or application log field. Production fails closed when the required binding or key material is unavailable.
- Product problem reports are anonymous and separate from public video moderation. D1 stores only the short message, current `find`/`upload`/`mine` view, lifecycle timestamps, and resolving administrator; it stores no reporter identity, contact field, or raw client address. Submission uses the same HMAC pseudonymization pattern with a separate limiter namespace.
- Upload requires authentication, ownership check, provider ID verification, a 200,000,000-byte source-file limit, and 5–60 second duration. The browser does not transcode before the direct provider upload.
- Target user-entered data is limited to spot/time, public name, favorite, identity visibility, an optional fun reaction, and one optional 100-character uploader supplement. No manual condition values, uploader GPS, additional subjective tags, or public reply threads. The two optional subjective values never affect matching.
- Production secrets stay server-side. Development mocks require explicit development flags.
- Internal testing accepts at most 100 registered users. Existing LINE subjects can continue to authenticate after the cap is reached; a verified new subject at capacity creates no user or session, and the UI exposes only a generic capacity message.
- MVP moderation is trust-first: no per-video pre-publication review. Public reports are auditable but do not auto-hide content. Only the project administrator identified by `ADMIN_USER_ID` can list open reports and delist a video; ordinary uploader metadata edits cannot republish a delisted row.
- Reporting does not clear copyright, privacy, music, likeness, or minor-consent risks. Upload terms must put responsibility on the contributor, while legal/privacy/safety reports may still cause first-party delisting.

Deterministic expiry deletion and cost-route burst limits are implemented locally. Public candidate comparison deliberately loads no player, manifest, or video segment before an explicit play action. Protected owner download is also implemented locally, but Stream MP4 generation, delivery CORS, native file sharing, and the download fallback still require real-device end-to-end checks; Web Share support and target apps vary by browser and in-app WebView. Before public rollout: exercise expiry against staging, verify Stream upload/thumbnail/playback/download/origin behavior and deployed rate limits, test Chrome Android plus Safari iOS and LINE's in-app browser, configure the administrator, exercise reporting/delisting against staging, and add cost alarms.
