# Project principles

> 不預測浪好不好；只用社群共享的歷史實拍，呈現指定浪點與時間的預報可能長什麼樣。

This document records the product philosophy that must survive handoffs. `docs/PRODUCT.md` defines current UX scope; this file defines why the project exists and the boundaries an implementation must not quietly cross.

## Purpose and position

- 彼日浪影是非營利 side project，不與既有預報產品競爭，也不製作另一套衝浪預報。
- 使用者在不熟悉的浪點看到預報後，可以用相似歷史預報下的實拍理解浪可能長什麼樣。產品不宣稱浪一定如何、不判斷浪好不好，也不推薦衝浪板。
- 預報只能描述趨勢；地形、遮風與其他在地效應會讓實際浪況不同。影片保留這些模型難以表達的實地經驗。
- 核心資產是可重用的社群影片資料庫與 matching 方法。官方前端只是最小可用的資料入口與參考客戶端。
- 個人影片回顧、收藏與可選擇顯示的公開名稱是鼓勵貢獻的功能，不是私人雲端硬碟。

## Contributor-first commons

- 願意上傳影片的人是專案最重要的角色。資料量未形成前，產品價值有限；設計應優先減少上傳步驟與不必要欄位。
- 浪點必須在上傳前選定且不可稍後補選或變更；缺拍攝時間的影片保持私人，讓上傳者在七天內補齊。資料完整並公開時，才進入公共資料集。
- 公開影片預定以 [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/) 捐入數位公地。任何人可下載、重製、轉售或用於模型訓練；不是把模糊的「共同所有權」交給平台。
- CC0 只適用於上傳者有權釋出的著作權，不會消除畫面中第三人的肖像、隱私或其他權利。
- 公開授權不可因上傳者改變心意而撤回。侵權、隱私、安全或無權上傳的內容仍可從本站下架，但合法取得的既有副本無法追回。
- 影片應以浪況為主。海灘或海面廣角中人物僅附帶入鏡時，不要求上傳者逐一取得每個人的同意；若可辨識人物是主要拍攝對象，應先取得本人或未成年人監護人同意，否則裁切或模糊。
- 上傳介面必須直接說明公開與 CC0 後果，並以可展開的行內說明提供人物入鏡判斷與官方資料；不能用額外勾選或阻斷式彈窗增加步驟。系統須保存接受的條款版本。
- 影片、衍生片段／縮圖及可合法釋出的社群中繼資料可納入公地。Logo、程式碼與第三方預報資料各自受其授權約束，不自動成為 CC0。

## Minimal product

- 手機優先、三個分頁、能少按一下就少按一下。不要用 slogan、遊戲化、廣告或募款彈窗消耗耐心。
- 上傳影片長度為 10–60 秒，拍攝時間最多回填七天。信任貢獻者，只做成本、安全與明顯濫用所需的最低限度自動檢查，不做逐片事前人工審核。
- 公開影片必須提供檢舉入口。檢舉是發現問題與執行下架的機制，不會消除第三方人物、音樂、著作權或隱私風險；仍須有上傳者責任條款、檢舉紀錄與管理者一鍵下架能力。
- 上傳者可選填那天玩得開心／不開心；沒下水可不填。另保留最多 100 字的「上傳者補充」，承接人的分享欲。兩者都不代表客觀浪質、不進入 matching、不影響排序；不再增加其他主觀欄位或留言串。

## Forecast and matching integrity

- 歷史匹配必須使用當時已發布、使用者實際有機會看到的預報快照。保存來源、模型、run、`issued_at`、`valid_at`、`lead_hours` 與網格。
- 使用者只選浪點、`Asia/Taipei` 日曆日偏移 0–4 與當日 05:00–19:00 的整點，不可選分鐘或已經過去的時間。影片實際拍攝時間可保留分鐘與秒，但台北時間的小時必須介於 05–19。系統使用查詢當下最新可得、有效時間接近目標的預報；歷史影片則使用拍攝當時最新可得、有效時間接近拍攝時間的預報。`lead_hours` 仍保存供追溯，但不要求與目前查詢相同。不能改用拍攝後發布的 run 或浪發生後吸收新觀測重建的 reanalysis／hindcast。
- 事後分析、浮標或其他觀測可作為獨立資料，用來描述或評估實況；必須明確標型別，不能覆寫預報快照或混成同一特徵。
- CWA、ECMWF WAM 與其他來源各自保留和計算，不平均原始值。日偏移 0–2 要求 CWA 與 ECMWF 各自達到最低資料涵蓋率，再以兩個來源各 50% 的權重合成一個相似度；日偏移 3–4 明確改用 ECMWF-only，相似度就是 ECMWF 的來源內分數。介面必須揭露這個分數定義差異。來源內仍採可解釋的正規化距離／KNN；資料足夠後才用非監督方法離線探索。

## Sustainability and exit

- 每月基礎設施硬上限為 NT$1,000。開放授權不等於專案必須永久補貼 API 或下載頻寬；可限速，合作方的大量使用應自行鏡像或負擔增量成本。
- 歡迎與既有預報產品合作並提供 API。資料權利不因合作方是否營利而改變。
- Buy Me a Coffee 只放在「關於／支持專案」，公開成本與資助，不插入上傳流程、影片播放或彈窗。
- 本站以拍攝時間起算，最多託管完整影片三年；這是保存目標與上限，不是無條件 uptime SLA。外部已取得的 CC0 副本不因本站刪除而失效。
- 首波正式浪點為烏石港、雙獅、無尾、蜜月灣、金樽、北東河、漁光島、南灣。新浪點應在有貢獻者與足夠資料累積可能性時才開放，不為目錄數量擴張。
- 公開資料應有可匯出的 manifest／中繼資料格式，讓合作方或社群在專案停止時仍可接手；本站不承諾永久代管外部副本。

## Decision discipline

- 不以會員數、瀏覽量或 slogan 當成功。啟動後只用最低成本的營運數字判斷：查詢是否找到足夠實拍、各浪點資料是否足以配對、上傳是否順利、成本是否逼近上限。
- 不為三年後可能保留的匿名統計預先設計。接近首次到期時再決定哪些非個人彙總仍有實際用途。
- 遇到方便開發但會模糊資料來源、增加使用者步驟、把主觀感受當客觀真相，或讓專案承擔不可控成本的方案，預設拒絕。
